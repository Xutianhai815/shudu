# 0.1.0 体验版与提审清单

这份清单用于把当前小游戏工程推进到“可上传体验版、可尝试提交审核”的状态。目标不是首版完美，而是尽快在微信端获得真实试玩反馈，并尽早暴露审核风险。

## 当前版本定位

- 版本建议：`0.1.0`
- 版本类型：内部体验版 + 首次审核探路版
- 核心体验：基础数独关卡、菜单选关、本地进度、通关弹层、每日脑力报告
- 安全边界：所有脑力反馈均为娱乐数值，不代表医学效果

## 上传前必须完成

- [ ] 在本地运行全量测试：`node --test minigame/test/*.test.cjs`
- [ ] 重新生成视觉快照：`node minigame/test/render-snapshots.js`
- [ ] 在微信开发者工具中编译通过，没有启动报错
- [ ] 在开发者工具模拟器中确认首页、关卡、通关弹层都能正常显示
- [ ] 用真机预览测试至少 1 台 iPhone 和 1 台 Android
- [ ] 确认数独页顶部不显示调试完成、假计时器或未启用的暂停按钮
- [ ] 确认上传包排除了 `test/`、`tools/`、`artifacts/` 和 `README.md`

## 真机试玩重点

- [ ] 首屏是否能理解“开始实验 / 继续实验 / 关卡卡片”
- [ ] 棋盘触摸是否准确，尤其是小屏手机
- [ ] 数字键、草稿、撤销、擦除是否顺手
- [ ] 数字键、选格、填数、工具键、通关音效是否克制且不刺耳
- [ ] 手机静音模式下音效是否符合预期
- [ ] 通关弹层是否能让玩家理解“今日训练”和“大脑除锈”
- [ ] 菜单页“今日报告”是否让人有继续玩一局的动机
- [ ] `再来一局` 和 `下一关` 是否符合预期
- [ ] 退出再进后进度是否保留
- [ ] 是否出现“像医学承诺”的误解

1. 打开微信开发者工具。
2. 导入项目目录：`/Users/tianhai/Documents/微信小游戏/minigame`。
3. 确认 AppID：`wx2ae48d4332aebd75`。
4. 点击“编译”，确认模拟器可运行。
5. 点击“预览”，用手机扫码做一次真机预览。
6. 点击“上传”，版本号建议填 `0.1.0`。
7. 上传后进入微信公众平台/小游戏后台版本管理，把该开发版本设为体验版。
8. 将你和同事加入体验成员，分发体验二维码。

## 首审可接受风险

首版可能因为类目、名称、截图、文案、功能完整度或体验问题被打回。这个阶段的目标是尽早拿到明确反馈，所以只要没有明显违规文案、启动崩溃、无法操作、或生产环境调试入口泄露，就可以尝试提交。
