# 华为 H5 快游戏迁移设计

## 背景

当前数独小游戏已经形成一个微信小游戏工程，主体是 `Canvas + JavaScript`：

- `minigame/game.js` 负责微信运行时入口、触摸、存储、音频、菜单/游戏场景切换。
- `minigame/src/renderer.js` 负责 Canvas 绘制。
- `minigame/src/puzzle.js`、`levels.js`、`progress.js`、`derust.js`、`companion-feedback.js` 等模块已经基本平台无关。
- 当前功能包含闯关、自由训练、关卡进度、本地存档、音效、完成反馈、重复提醒、安静陪伴系统。

华为快游戏官方提供 `H5 版本` 和 `Runtime 版本` 两种开发路线。考虑到本项目不是 Cocos/Laya/Egret 等引擎工程，且数独是轻量 2D Canvas 游戏，第一版选择 `H5 快游戏` 路线：先把现有游戏抽出为普通 H5 可运行版本，再通过华为快应用 IDE 封装为快游戏。

## 目标

第一版目标是完成一个可真机体验、可打包为华为快游戏 `RPK` 的 H5 版本，同时不破坏当前微信小游戏版本。

具体目标：

- 在浏览器/H5 环境中完整运行当前数独游戏。
- 复用现有游戏逻辑、关卡、Canvas 渲染和交互体验。
- 新增平台适配层，让微信入口和 H5 入口共享核心游戏控制逻辑。
- 创建华为 H5 快游戏包装工程所需的资源和说明。
- 生成可交给华为快应用 IDE 包装/调试的 H5 构建产物。
- 保持微信小游戏测试继续通过。
- 为后续接入华为账号、游戏服务、防沉迷、广告、分析服务预留清晰边界。

## 非目标

第一版不做以下内容：

- 不重写为 Cocos/Laya/Egret/Runtime 快游戏。
- 不接入华为账号登录。
- 不接入华为游戏服务、防沉迷、实名认证。
- 不接入广告、内购、支付、排行榜、云存档。
- 不做 HarmonyOS 原生应用或元服务。
- 不改变现有数独玩法和 UI 结构。
- 不把微信小游戏工程删除或迁移成单平台工程。

## 产品形态

### 用户侧体验

H5 快游戏版本应尽量与微信小游戏版本一致：

- 首页进入后仍展示数独实验室主视觉。
- 用户可以选择闯关实验或自由训练。
- 闯关实验保留主线推进。
- 自由训练保留难度选择。
- 游戏页保留数字输入、草稿模式、重开确认、清除、完成反馈、局内轻提示。
- 完成页保留“大脑除锈”正向反馈。

如果华为快游戏容器对顶部安全区、全屏、音频策略、触摸事件存在差异，H5 版本可以做轻微适配，但不能改变核心体验。

### 开发侧体验

开发者应能使用以下流程验证：

1. 运行 Node 测试，确认核心逻辑不回退。
2. 启动 H5 本地预览，在浏览器中完整玩一局。
3. 生成 H5 构建产物。
4. 使用华为快应用 IDE 创建或打开 H5 快游戏包装工程。
5. 在真机或快游戏调试工具中运行。
6. 生成 release `RPK`，进入后续提交审核准备。

## 技术路线

### 推荐路线：平台适配层 + 双入口

新增一个平台抽象层，统一提供游戏运行所需能力：

- Canvas 创建和尺寸获取。
- 触摸事件注册。
- 窗口尺寸变化监听。
- 本地存储读取、写入、清除。
- 音频创建和播放。
- 动画帧。
- 设备倾斜/加速度能力。
- 顶部安全区信息。
- 弹窗确认。
- 环境标识，例如 `wechat`、`h5`、`huaweiQuickGame`。

微信入口继续使用微信 API；H5 入口使用浏览器 API。未来如果需要更深度接入华为快游戏 API，可以新增 `huaweiQuickGamePlatform`，而不是把平台判断散落在游戏逻辑里。

### 文件边界

建议新增或调整以下文件：

- 新增 `minigame/src/app-runtime.js`：平台无关的游戏控制器，承接当前 `game.js` 中大部分状态机逻辑。
- 新增 `minigame/src/platform/wechat-platform.js`：封装当前 `wx` 能力。
- 新增 `minigame/src/platform/h5-platform.js`：封装浏览器能力。
- 修改 `minigame/game.js`：变成很薄的微信入口，只创建微信平台并启动 `app-runtime`。
- 新增 `huawei-h5/index.html`：H5 预览入口。
- 新增 `huawei-h5/main.js`：创建 H5 平台并启动游戏。
- 新增 `huawei-h5/styles.css`：页面全屏、背景、Canvas 尺寸样式。
- 新增 `huawei-h5/README.md`：华为快游戏 H5 包装、调试、打包说明。

如果第一版不引入打包工具，可以先使用普通 `<script>` 加载一个浏览器兼容 bundle。若现有 CommonJS 模块难以直接在浏览器运行，应新增轻量构建脚本，把 `minigame/src` 和 H5 入口打成单文件 bundle。

### 运行时接口

平台对象建议提供以下接口：

```js
{
  createCanvas(),
  getSystemInfo(),
  getTopInset(),
  onTouchStart(handler),
  onWindowResize(handler),
  showModal(options),
  getStorageSync(key),
  setStorageSync(key, value),
  removeStorageSync(key),
  createInnerAudioContext(),
  requestAnimationFrame(callback),
  cancelAnimationFrame(frame),
  startAccelerometer(options),
  stopAccelerometer(),
  onAccelerometerChange(handler),
  offAccelerometerChange(handler),
  getEnvironment()
}
```

微信平台可以直接转调 `wx`；H5 平台需要用浏览器能力模拟等价行为：

- `createCanvas()`：读取页面中的 `<canvas>`。
- `getSystemInfo()`：使用 `window.innerWidth`、`window.innerHeight`、`devicePixelRatio`。
- `getTopInset()`：默认 `0`，后续可用 CSS `env(safe-area-inset-top)` 估算。
- `onTouchStart()`：同时监听 `touchstart` 和 `mousedown`，方便桌面调试。
- `showModal()`：第一版可用 `window.confirm()` 实现，后续再改成自绘确认弹层。
- `getStorageSync()` / `setStorageSync()`：使用 `localStorage`，读写 JSON。
- `createInnerAudioContext()`：使用 `HTMLAudioElement` 或 Web Audio 的轻量封装。
- `startAccelerometer()`：优先使用 `DeviceMotionEvent`，不可用时静默降级。

## 存储策略

H5 版本第一版继续使用本地存储，不接云服务。

存储 key 可以继续使用 `lab-lines-progress-v1`，但平台实现需要保证：

- 微信和 H5 各自在自己的沙箱内存储，不会互相污染。
- H5 localStorage 数据异常时走现有 `normalizeProgress()` 容错。
- 练习模式和闯关模式的存档边界保持现有设计。

未来如果接入华为账号或云存档，应另起 `progress-sync` 设计，不在本轮混入。

## 音频策略

H5 环境的音频播放通常受用户手势限制。第一版策略：

- 保留按键音和完成音。
- 音频初始化失败时静默降级，不阻塞游戏。
- 首次用户触摸后再允许播放音频。
- 不新增背景音乐。
- 不为华为版本新增独立音效资源。

## Canvas 与适配

H5 页面应采用单 Canvas 全屏布局：

- `body` 和 `html` 高度 `100%`，无滚动条。
- Canvas 使用 CSS 填满视口。
- DPR 仍由 runtime 按平台信息设置。
- 竖屏为第一版唯一支持方向。
- 如果浏览器或快游戏容器尺寸变化，应触发重新布局。

华为快游戏包装时，显示配置应使用全屏和竖屏方向；具体字段以华为快应用 IDE 生成的 `manifest.json` 为准。

## 华为快游戏包装

第一版工程目标不是在代码仓库中直接生成最终 `RPK`，而是准备可被华为快应用 IDE 包装的 H5 产物和操作文档。

包装流程建议：

1. 在华为快应用 IDE 中创建 H5 快游戏项目。
2. 设置应用名称、包名、图标、版本号、竖屏方向和全屏显示。
3. 将 H5 构建产物配置为加载目标。
4. 使用真机或快游戏调试工具运行。
5. 使用 IDE 打包正式版本，生成 `dist` 目录下的 `RPK`。
6. 在 AppGallery Connect 中准备提交审核。

第一版可以先采用本地 H5 资源随包方案；如果 IDE 模板要求配置 URL，则先使用本地可访问的测试地址验证，正式提交前再决定是否改为线上托管或离线资源方案。

## 华为开发者准备事项

这些事项通常需要开发者账号和人工操作，代码实现不能完全代替：

- 注册并认证华为开发者账号。
- 在 AppGallery Connect 创建项目并添加快游戏。
- 确认应用名称、包名、分类、图标、隐私政策、版权归属。
- 生成签名证书和证书指纹。
- 在 AppGallery Connect 中配置证书指纹。
- 安装华为快应用 IDE。
- 准备华为真机或可用调试环境。
- 后续如接入华为账号、游戏服务、分析服务，需要在 API 管理中开启对应能力。

## 审核与合规边界

第一版虽然不接入账号、广告、支付，但仍需要提前准备：

- 隐私政策页面：说明本地存档、音频、设备传感器使用情况。
- 用户协议或游戏说明：说明这是休闲益智游戏。
- “大脑除锈”文案合规：继续避免医学承诺，不宣称预防疾病或治疗效果。
- 未成年人相关要求：如果华为审核要求游戏类必须接入登录/防沉迷，则需要进入第二阶段专项接入。
- 版权材料：图标、名称、音效、UI 素材来源需可说明。

## 测试策略

### 自动化测试

保留并新增以下测试：

- 现有 `node --test minigame/test/*.test.cjs` 必须通过。
- 新增 `app-runtime` 测试，验证平台无关状态机仍能启动、进入游戏、完成关卡、保存进度。
- 新增 `h5-platform` 测试，验证 localStorage、弹窗确认、系统信息、音频降级。
- 新增 H5 smoke test，验证浏览器入口能创建 Canvas 并绘制首页。

### 手动测试

H5 本地预览：

- 首页能显示。
- 闯关实验能进入。
- 自由训练能选择难度并进入。
- 数字输入、草稿、清除、重开确认可用。
- 完成一局后显示完成反馈。
- 刷新页面后能继续未完成局。

华为快游戏调试：

- RPK 或调试包能在真机启动。
- 竖屏和全屏正常。
- 触摸位置准确。
- 音效不会导致崩溃。
- 返回首页、继续游戏、重开、完成流程正常。

## 分阶段计划

### 阶段一：H5 可运行

目标：普通浏览器里跑起来，不依赖微信 `wx`。

交付：

- 平台适配层。
- H5 入口。
- 本地预览文档。
- 自动化测试。

### 阶段二：华为快游戏包装

目标：能通过华为快应用 IDE 调试并生成 `RPK`。

交付：

- H5 构建产物。
- 华为快游戏包装说明。
- 图标和基础 manifest 字段建议。
- 真机调试 checklist。

### 阶段三：审核前补齐

目标：进入可提交审核状态。

交付：

- 隐私政策和用户协议文本。
- 应用介绍、截图、图标素材。
- 包名、版本号、签名证书记录。
- 审核自查表。

### 阶段四：华为能力接入

目标：根据审核要求或运营需求接入 HMS 能力。

可选方向：

- 华为账号登录。
- 游戏服务和防沉迷。
- 分析服务。
- 广告服务。
- 游戏升级或渠道统计。

## 风险与应对

### 风险一：CommonJS 模块不能直接在浏览器运行

应对：新增轻量构建步骤，将游戏代码打包为浏览器 bundle。不要手动复制模块代码。

### 风险二：H5 音频自动播放限制

应对：音频按用户交互后播放，失败时静默降级。

### 风险三：快游戏容器与浏览器事件差异

应对：平台层集中处理触摸、尺寸、DPR、弹窗和动画帧差异，核心逻辑不感知容器。

### 风险四：华为审核要求游戏服务或防沉迷

应对：第一版先完成可运行包；如果审核要求强制接入，再开启第二阶段专项 spec。

### 风险五：线上 H5 URL 与离线资源选择不确定

应对：第一版文档同时记录两种路径。优先尝试离线随包资源；如果 IDE 模板或审核流程更适合 URL，再切换到稳定 HTTPS 托管。

## 验收标准

- 微信小游戏现有测试全部通过。
- H5 本地预览可完整玩一局。
- H5 本地预览可刷新恢复存档。
- H5 本地预览完成页不出现医学承诺。
- 华为快应用 IDE 能运行 H5 快游戏项目。
- 能生成可供后续审核准备的 `RPK`。
- 文档中明确记录华为开发者后台、证书、包名、图标、隐私政策等人工准备项。

## 后续决策点

完成第一版 H5 快游戏原型后，再根据真机表现选择：

- 继续 H5 路线，上架快游戏。
- H5 路线保留为轻量渠道，同时启动 HarmonyOS 原生应用研究。
- 如果性能或审核限制明显，再评估 Runtime/引擎重构。
