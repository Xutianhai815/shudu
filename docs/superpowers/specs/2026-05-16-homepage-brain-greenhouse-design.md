# 首页脑力温室设计 Spec

## 背景

当前新用户首次进入首页时，页面信息过少，主要只有一个“开始实验”按钮；“今日报告”模块在早期内容不足，容易显得空。我们已确认采用 `A. 脑力温室` 方向，将首页改成更有欢迎感和品牌记忆点的首屏。

## 目标

- 移除首页“今日报告”模块。
- 让新用户首页从“空白 + 按钮”变成一个安静、明亮、有轻微实验感的入口。
- 保持首页简单，不展示 12 个关卡列表，不制造选择压力。
- 本轮不做背景音乐；背景音乐后续作为独立任务再引入。

## 非目标

- 不在本轮恢复关卡选择列表。
- 不在首页展示今日训练次数、累计除锈百分比等报告信息。
- 不在首页引入复杂任务系统、签到、成就墙或商业化入口。
- 不使用医疗承诺或疾病风险相关文案。

## 首页内容结构

### 标题区

- 主标题：`数独实验室`
- 英文小标题：`Lab Lines Sudoku`
- 副文案：`每天打开一局，给大脑做一次轻量热身。`

标题区应继续避开微信顶部安全区，不能被摄像头、小程序胶囊按钮或状态栏遮挡。

### 主视觉

首页中心加入一个 `9×9 漂浮线索盘`：

- 由 81 个细格组成，必须一眼能识别为数独棋盘。
- 每 3 行、3 列用更粗的宫线区分 3×3 宫。
- 少量格子放入数字，避免像纯装饰图案。
- 少量格子用青绿和琥珀做线索高亮，表达“线索被激活”。
- 色彩以深绿、奶白、青绿、琥珀为主。
- 视觉形态轻、圆润、略微漂浮，不做机械重工业风。
- 允许少量半透明粒子或柔雾点缀，避免空白，但不能遮挡按钮。

### 操作区

- 无存档时，只显示一个主按钮：`开始实验`。
- 有未完成存档时，显示 `继续实验` 和 `开始新实验`。
- 按钮整体从原底部贴边位置上移约 34-44px，底部保留更明显的呼吸空间。
- 移除原先建议的底部轻提示 `今日第一局 · 从 3 分钟开始`。
- 首页不显示“今日报告”或任何替代报告文案。

## 视觉风格

### 视觉 thesis

首页像一个安静明亮的脑力温室：浅绿、暖米色、柔光、漂浮线索，让用户觉得“开始一局”是轻松的热身，而不是考试。

### 色彩

- 背景：浅绿到暖米色渐变。
- 主文字：深墨绿。
- 强调色：青绿，少量琥珀。
- 按钮：深墨绿底、奶白文字。

### 构图

- 首屏采用纵向 poster 式构图。
- 标题在上，主视觉在中，按钮在下。
- 按钮仍然是最强可点击元素。
- 页面不使用多卡片堆叠，不用统计条填空。

## 动效设计

动效只做三类轻量效果：

- 入口动效：标题、主视觉、按钮依次轻微上浮出现。
- 主视觉动效：`9×9 漂浮线索盘`缓慢上下漂浮，周期约 4-6 秒。
- 背景动效：少量粒子缓慢漂移或透明度呼吸。

动效约束：

- 不能影响点击命中区域。
- 不能闪烁或高频运动。
- 不能让首页显得像广告页。
- 在低端机上可以降级为静态绘制。

## 背景音乐边界

本轮不实现背景音乐，也不新增 BGM 文件、音频开关或自动播放逻辑。背景音乐后续作为独立小步能力引入，而不是和首页视觉一次性耦合。

推荐策略：

- 使用现有 `soundManager` 的思路扩展为 `audioManager`，支持音效和 BGM。
- BGM 使用短循环音频，风格是低音量、低频率、轻实验室氛围，不使用强旋律。
- 不在首页无交互时强行播放；优先在用户点击开始、继续或音频开关后启动。
- 默认遵循系统静音开关。
- 需要提供关闭入口，后续可以放在首页或游戏页的轻量音频按钮里。
- 音量建议低于按键音效，避免影响长局思考。

后续如果要加入，建议单独做一轮“轻背景音乐与音频开关”任务，包含音频素材、循环测试、真机试听和关闭入口。

## 数据与状态

首页布局仍由 `createMenuLayout` 生成：

- `hasActiveRun` 决定按钮数量。
- `completedLevelIds` 可继续保存，但不用于首页报告展示。
- `dailyReportSummary` 不再传入首页布局或不再渲染。

建议新增首页装饰布局字段：

- `heroBoard`：主视觉位置、尺寸、81 个格子的数字和色调。
- `ambientParticles`：背景粒子位置、半径、透明度。
- `animationSeed`：用于渲染可重复的轻微运动状态。

## 渲染方案

`renderMenu` 调整为：

1. 绘制浅绿暖米色背景。
2. 绘制柔和装饰粒子。
3. 绘制标题与副文案。
4. 绘制 `9×9 漂浮线索盘`。
5. 绘制按钮。

删除或停用：

- `drawDerustSummary`
- 首页 `DEFAULT_DERUST_SUMMARY` 的渲染路径
- 视觉快照里的“今日报告”示例

## 测试要求

- `createMenuLayout` 在无完成记录时仍有 `heroBoard`，页面不再只有按钮。
- `heroBoard.cells` 必须包含 81 个格子。
- 首页按钮底部必须比原来更高，常规屏幕至少留出 `32px` 额外空间。
- 首页无论是否有完成记录，都不暴露 `derustSummary.visible === true`。
- 首页不渲染 `今日报告`、`今日除锈`、`累计除锈`。
- 有存档时，继续/开始新实验按钮仍可命中。
- 常见屏幕尺寸下，标题、主视觉、按钮不溢出底部。
- SVG 视觉快照能看到首页主视觉和按钮。

## 验收标准

- 新用户首页第一眼能看到明确品牌、主视觉和开始按钮。
- 首页主视觉必须明显像数独棋盘，而不是 3×3 装饰格。
- 首页不再显示“今日报告”模块。
- 首页没有底部轻提示 `今日第一局 · 从 3 分钟开始`。
- 首屏仍然轻、干净、低压力，不像活动页或广告页。
- 本轮没有背景音乐相关代码、素材或入口。

## Spec 自检

- 无 `TBD` 或未定范围。
- 首页视觉改造和背景音乐已拆开；本轮只实现首页视觉。
- 已明确移除底部轻提示和今日报告。
- 已明确不做医疗承诺文案。
