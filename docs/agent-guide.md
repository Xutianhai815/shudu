# Agent 协作指南

本指南用于避免多个 agent 在不同平台重复开发同一套数独功能。开始任何新任务前，请先阅读本文件和对应 spec/plan。

## 当前平台

- `minigame/`：微信小游戏 Canvas 版本，是当前主要可玩版本和审核版本。
- `huawei-h5/`：H5 预览与华为快游戏包装方向，复用小游戏共享运行时。
- `harmonyos/`：HarmonyOS 原生 ArkTS/ArkUI 工程，正在迁移核心玩法。

## 必须复用的核心能力

以下能力属于跨平台核心逻辑，不能在某个平台里重新发明一套不兼容版本：

- 数独关卡数据：关卡 ID、题面、答案、难度曲线。
- 数独状态机：选格、填数、草稿、清除、重开、撤销、完成判断。
- 重复提醒：只提醒行、列、宫重复，不判断答案对错。
- 闯关系统：24 关进度、完成后进入下一关。
- 自由练习：热身、稳定、标准、进阶四档训练难度和推荐规则。
- 成长系统：连续练习、今日完成局数、完成页成长反馈。
- 审核安全文案：不出现疾病预防、治疗效果、概率降低、金币、会员、红包等高风险表达。

## 平台适配边界

平台目录可以独立处理：

- UI 布局和视觉表现。
- 触摸、鼠标、键盘、遥感器等输入适配。
- 音频、本地存储、生命周期、平台菜单安全区。
- 构建、预览、上传、打包和应用商店配置。

如果你要改的是核心规则或数据，请优先修改共享源头，并补充对应测试；不要只在某个平台 UI 里复制逻辑。

## 开发流程

1. 先确认任务属于核心逻辑还是平台适配。
2. 搜索已有实现，优先复用 `minigame/src/` 中已经验证过的逻辑。
3. 修改核心逻辑时，必须更新或新增 `minigame/test/*.test.cjs`。
4. 修改平台 UI 时，至少确认不会破坏核心测试。
5. 提交前运行：

```sh
node --test minigame/test/*.test.cjs
```

如果改动影响 H5，再运行：

```sh
node huawei-h5/build.js
```

如果改动影响微信小游戏界面，再运行：

```sh
node minigame/tools/render-snapshots.js
```

## Pull Request 要求

PR 描述应包含：

- 本次改动属于核心逻辑还是平台适配。
- 是否复用了已有核心模块。
- 已运行的验证命令和结果。
- 如果没有运行某项验证，说明原因。

不要提交：

- `output/` 中的二维码、上传信息或临时预览文件。
- `node_modules/`、`dist/`、`build/` 等构建产物。
- 未确认用途的调试开关、测试按钮、审核高风险文案。
